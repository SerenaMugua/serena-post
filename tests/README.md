# 自动测试

运行：`npm test`（几秒钟）。全部 ✔ 才算老功能没被改坏；出现 ✖ 先看是哪条，再决定是代码改错了，还是功能本来就要变（那就同步改测试，并告诉作者）。

| 文件 | 管什么 |
| --- | --- |
| `tidy.test.ts` | 整理全文：「一、」→ 章节标题、「（一）」→ 小标题、空行合并、不动代码块和笔记属性 |
| `heading-number.test.ts` | 标题自带「一、/（三）/第二章/4.」时去掉，不重复编号 |
| `render.test.ts` | 15 套排版都能渲染；Serena 蓝白配色；9 种章节样式；IP 头像；结束标记；`==高亮==` |
| `relay.test.ts` | 内置 X 中转真的启动一次，收草稿、读草稿、删草稿（用临时文件夹，不碰真实 `~/.kaitox`） |
| `guard.test.ts` | 守门：插件 id、版本号一致、设置字段名、中转端口 8765、密钥键名、老用户迁移、笔记属性名、不用 form-data、开源声明、Release 文件名 |

`guard.test.ts` 对应项目文档里的「禁区」。改到那里报错，说明碰了不能碰的东西，先问作者。

GitHub 上也会自动跑：推到 main 时跑「自动测试」；推版本标签时先测试，不通过就不发布。

> 测试只覆盖不需要真实账号的部分。真推公众号、在 X 里建草稿、界面点击，还是要在测试库里用 Computer Use 测。

# 发布与上架步骤（给维护者）

## 一、发一个 Release（BRAT 和 zip 安装都靠它）

1. 在 `CHANGELOG.md` 最上面写好这一版的说明，标题格式是 `## 1.1.0`。
2. 改版本号：`npm version 1.1.0`（会同时改 `package.json`、`manifest.json`、`versions.json`，并打一个不带 v 的标签）。
   第一次发 1.1.0 时版本号已经改好了，直接打标签：`git tag 1.1.0`。
3. 推送：`git push origin main --tags`。
4. 等 GitHub Actions 跑完（仓库的 Actions 页），Releases 里会出现：
   `main.js`、`manifest.json`、`styles.css`、`serena-post-1.1.0.zip`。

## 二、申请上架 Obsidian 社区插件市场

前提：仓库是公开的，至少有一个 Release，README 和 LICENSE 都在仓库根目录。

1. 打开 https://github.com/obsidianmd/obsidian-releases ，点 Fork。
2. 在你 fork 的仓库里编辑 `community-plugins.json`，在**最后**加一项：

```json
{
	"id": "serena-post",
	"name": "SerenaPost",
	"author": "Serena 木瓜",
	"description": "Format notes for WeChat Official Accounts and push them to WeChat drafts and X Article drafts in one click, with live preview, layout themes and pre-publish checks.",
	"repo": "SerenaMugua/serena-post"
}
```

   注意前一项后面要补一个英文逗号。`description` 必须和 `manifest.json` 里完全一致。
3. 提交后点「Contribute → Open pull request」，标题写 `Add plugin: SerenaPost`，按模板勾选清单。
4. 机器人会自动检查；有问题会在 PR 里留言，按提示改好再推一个新版本即可。人工审核通常要几周。

## 三、审核常见要求（已处理）

- `id` / `name` / `description` 里不含 “Obsidian”，描述以句号结尾 ✅
- `isDesktopOnly: true`（用到了本地 http 服务和 Node 模块）✅
- README 说明了网络访问和库外文件读写（见「隐私与网络」）✅
- 没有默认快捷键，命令名不重复插件名 ✅
- 不用 `innerHTML` 写入不可信内容（统一用 `sanitizeHTMLToDom`）✅
